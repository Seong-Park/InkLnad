## 실제 이동 좌표 JSON 정밀도 회귀 수정

root 실제 combat_playthrough의 이동 중 autosave verify_failed를 추가 인계받았다. 실패 원인은 Dictionary 정규화만으로 해결되지 않는다. Vector2의 float32 값이 Dictionary의 float64로 승격된 값(특히 y=260.908233642578125)을 JSON.stringify 기본 정밀도가 260.908233642578로 줄여 읽기 결과와 원본의 엄격 동등 비교가 실패한다. 보고에 표시된 짧은 좌표 리터럴을 그대로 Dictionary에 넣는 테스트는 이 손실을 재현하지 못했다.

save unit regression은 Vector2(280.091796875,260.908233642578) 생성 후 .x/.y를 last_safe_point에 넣어 실제 런타임 변환을 재현한다. 수정 전 두 assertion(저장 성공/정확한 readback)이 실패하고 exit1이었다(chunk925339). SaveStore의 snapshot/preferences 직렬화를 JSON.stringify(value, "", true, true)로 수정하여 fourth full_precision 인자를 켰다. Godot4.7.2에서 이 4인자 호출이 compile/run되고 수정 후 SAVE PASS, INK_SAVE_PASS, failures0, exit0(chunk299dbb)였다. fake readback mismatch 거절 및 원본 rollback 검증은 유지됐다. 비교 tolerance로 검증을 느슨하게 하지 않았다.

재사용 교훈 후보: 저장 roundtrip 테스트에는 Vector2→Dictionary 실제 좌표 변환을 포함하고 full_precision=true를 사용한다. 시도한 실패 접근은 int/float normalize만 적용하기와 표시된 짧은 숫자를 재입력하기였다. 이 런타임의 소유 범위는 Store/test/reports이므로 프로젝트 skill 파일을 작성하지 않았으며 master가 matching lesson 갱신 여부를 결정할 수 있도록 검증 근거를 인계한다. 실제 combat_playthrough 재실행은 root가 소유한다.

## JSON canonical payload 보완

root 실제 전투 frame1199에서는 full_precision=true 이후에도 Vector2(12.0042877197266,12.0664978027344)의 JSON 파싱 결과가 원본 Variant보다 1 ULP 달라 verify_failed가 재발했다. full_precision만으로 모든 숫자의 raw Variant 일치를 보장한다는 이전 결론을 좁힌다. 새 회귀는 이 좌표 및 viewport 부근 Vector2(1279.123413085938,719.987670898438)를 포함한다. 수정 전 fractional commit이 실패해 exit1(chunk90cc1e)이었다.

최종 방식은 payload=JSON.stringify(snapshot,"",true,true)를 한 번 만들고 그 payload의 JSON.parse_string 결과에 schema 검증·숫자 정규화를 적용하여 expected를 만든다. tmp와 최종파일은 schema를 검증하며 최종 전체 snapshot을 expected와 엄격 비교한다. 허용 오차나 일부 필드 제외를 사용하지 않는다. fake readback 내용 불일치와 rollback 테스트는 계속 통과한다. EconomyService는 원본 candidate 대신 saved.snapshot으로 메모리 상태를 확정해 디스크와 같다. 서비스 메모리/디스크 일치 회귀도 포함했다.

수정 후 SAVE PASS/INK_SAVE_PASS failures0 exit0(chunk8e9081), ECONOMY PASS/INK_ECONOMY_PASS failures0 exit0(chunk02fa64). 원본 candidate 적용으로 되돌린 서비스는 메모리/디스크 동등 테스트를 실패하여 이 변경의 필요성도 별도 확인했다. 최종 서비스는 saved.snapshot 적용으로 다시 통과했다. root 실제 combat rerun과 이 단위 검증을 구분한다.

재사용 교훈의 최종 범위: JSON 저장 검증 기준은 실제 serialized payload의 parse/validate/normalize canonical 값이며, 성공 메모리도 그 값으로 확정한다. Vector2 실제값 회귀가 필요하다. raw Variant equality, normalize만 적용, full_precision만 적용은 각 단계에서 배제된 접근이다.
