# 기사 걷기 36프레임 적용

2026-10-03 / Godot 4.7.2

요청에 따라 걷기 36개 프레임을 6×6 투명 시트로 생성했다. 대기 8프레임 유지. 걷기 54fps, 기존 주기 8/12 = 36/54 = 약 0.667초 및 이동 속도 180 유지. 상체와 팔 동작을 포함한 그림 사용, 셀 고정 기준점으로 정렬. 36개 Atlas 범위 유효, raster 해시 모두 서로 다름. 그림의 자연스러움과 정확한 다리 교대는 해당 검사가 보장하지 않음.

MCP 프로젝트와 빈 열린 씬 확인, 라이브 게임 중지 후 파일 수정. Godot animation 스킬 적용. import 및 6개 테스트 전부 exit 0, 성공 marker 존재, stderr 비어 있음. 이동 검사가 걷기 프레임 36개와 모든 36개의 발 기준점을 확인하도록 변경됨.

실제 게임 캡처: 최초 160장 시도는 subprocess 60초 timeout으로 실패, 합격 아님. 방향별 36회와 대기 4회씩 총 80회로 축소한 재시도는 exit 0, INK_MOTION_CAPTURE_PASS, stderr 비어 있음. 캡처 타이밍은 실제 렌더링 성능으로 누락될 수 있으며 80회가 모든 animation frame의 개별 캡처를 뜻하지 않음. frames/timing.json에 실제 재생 프레임 기록. 최초 실패의 여분 PNG는 보존되며 최종 GIF는 성공 timing.json의 80장만 사용함. 2배 카메라 및 HUD 숨김은 fixture 설정.

증거: docs/verification/player-walk-36/manifest.json, frames/timing.json, movement-preview.gif.

Self-learning 검토: 과다한 viewport PNG 저장으로 timeout 발생, 촬영 횟수를 줄여 성공. 이 단일 관찰은 본 보고서에 남기고 새 스킬은 만들지 않음. 사용자 권한/지침/설정 변경 및 커밋 없음.
