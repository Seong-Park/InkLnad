# 첫 10분 플레이 QA 수용 체크리스트

작성: planning-agent · 2026.10.03 17:38 KST  
검토 대상: master의 전체 흐름 인수, FE/BE 기능 검토, QA 실행 증거  
현재 상태: 체크리스트 제출. **아래 모든 실행 항목은 미검증**이며 구현 완료나 통과를 뜻하지 않는다.

기준: [승인 상세 기획](첫%2010분%20플레이%20상세%20기획-2026.10.03.1611.md), [구현 계획](첫%2010분%20플레이%20구현%20계획-2026.10.03.1615.md), game-direction v0.5, AGENTS.md. 수치·범위·저장 규칙을 새로 기획하지 않고 승인 기준을 수용 조건으로 옮겼다. 현재 병렬 구현 결과의 코드 검사·테스트는 이 과업에서 하지 않았다.

## 1. 판정·증거 규칙

- P0: 첫 여정 완료·자원/공격 규칙·저장 무결성의 필수 조건. 하나라도 실패하면 전체 인수 보류.
- P1: 안내·시각·접근성·대체 경로의 필수 검토. 도형 초안은 기능 인수에 허용하되 수채화 완성으로 표기하지 않는다. 핵심 상태를 읽지 못하면 P0로 올린다.
- P2: 외부 처음 사용자 관찰. 확보 전에는 기능 인수와 구분해 “사용자 이해 미검증”으로 기록한다.
- 상태는 미검증/통과/실패/조건부로 기록한다. 명령·조건·실제 결과·증거 경로·검토자가 없는 항목은 통과로 취급하지 않는다. 미구현은 미검증이다.

자동 검증은 Godot 4.7.2, 대상 프로젝트·현재 작업 버전, headless import, 실행 명령, stdout/stderr, 종료코드, 실패 수와 기대 마커를 기록한다. 통과는 해당 runner exit0+실패0+런타임 오류0+기대 마커 모두 필요하다. 마커는 `INK_GAMEPLAY_PASS`, `INK_ECONOMY_PASS`, `INK_SAVE_PASS`, `INK_FIRST_JOURNEY_PASS`. 타임아웃·에디터 실행 시작·설치 smoke fixture 통과는 게임 인수 증거가 아니다.

화면 검토는 실제 게임 Main.tscn에서 입력 방법·해상도·설정·실행 버전을 기록한 영상/연속 캡처가 필요하다. 한 정지 화면만으로 충전 시간·입력 취소·적 AI 통과를 판정하지 않는다. 저장 실패 테스트는 격리 저장 경로와 실패 주입 조건을 쓰며 실제 사용자 저장을 훼손하지 않는다.

## 6. P2 처음 사용자 이해와 master 전체 흐름

5명 중4명이 외부 설명 없이 고갈 해제·충전·귀환·두 잉크 구별을 수행하는 기존 목표를 그대로 사용한다. 모집·관찰이 없다면 목표 달성으로 기록하지 않는다. 각 참가자의 단계별 막힘, 추가 설명 여부, 수행 결과, 실제 소요시간을 익명으로 기록한다. 약10분은 강제 타이머가 아니므로 오래 걸린 이유를 튜토리얼·전투·길찾기·구매로 나눠 관찰한다.

master는 실제 전체 플레이 증거를 보고 다음을 판정한다: 그린 형상과 피해가 예측 가능한가, 기사 이동과 잔흔 유도가 의미 있는가, 고갈 후 다음 행동을 알아채는가, C완료·D선택·E잠금·F복원을 읽는가, 구매가 같은 조작으로 새 도구 시험까지 이어지는가. 숫자 튜닝 제안은 관찰 근거와 함께 planning-agent에 전달하고 별도 승인 없이 기준을 바꾸지 않는다.

## 7. 인수 제출 형식

QA 최종 보고서는 `ID | 상태 | 실행버전·조건 | 기대/실제 | 증거경로 | 담당/검토자 | 남은문제` 표로 작성한다. 증거는 구현 계획의 `docs/verification/first-journey/` 아래 로그·캡처·manifest에 연결하고 사용자 보고서는 reports 아래 날짜시간 제목을 사용한다. 자동통과와 실제화면통과, 외부사용자이해를 각각 구분한다.

이번 보고서는 승인 규칙을 다시 설계하지 않은 체크리스트다. 게임 파일을 수정하거나 runner를 실행하지 않았다. 수용 증거는 앞으로 QA/매니저가 확보하고 master가 전체 흐름을 검토한다.
