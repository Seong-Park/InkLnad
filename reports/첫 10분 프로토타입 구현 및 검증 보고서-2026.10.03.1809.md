# 첫 10분 프로토타입 구현 및 검증 보고서

2026.10.03 18:09 KST · Godot 4.7.2 · 현재 프로젝트 적용 · master 최종 검토

## 결과

승인 기획의 첫 여정이 실제 Main 씬에 구현됐다. 공방 훈련 → 연결 통로 → 공터 세 적 → 선택 전투 → 정예 → 꽃집 복원 → 공방 귀환 → 연필 구매·시험으로 이어진다. 기획 agent는 수용 기준을 정리했고, FE/BE 담당은 구현과 검토를 수행했다. master는 전체 흐름·실패 복구·실행 증거를 검토했다. 제한된 실행 슬롯을 재사용했으며 모든 역할이 동시에 상주하는 구조는 아니다.

실행: `godot/project.godot`을 열고 F6 대신 **F5(프로젝트 실행)**. WASD/방향키 이동, 마우스 왼쪽 드래그 공격, 버튼을 놓아 충전, E 상호작용, 1/2 도구 선택, Esc 일시정지. 메인 씬은 `res://scenes/gameplay/Main.tscn`이며 환경 검증 fixture가 아니다.

기사 주변 반경180 안에서 실제 선을 그린다. 붓/연필의 굵기·피해·소비·잔흔 수명을 분리했고, 덧칠 피해는 공유 간격으로 제한한다. 전투 잉크는100, 충전은 공격 해제0.5초 뒤3.5초 완충이다. 회수 잉크는 별도 재화다. 필수 경로74에서 연필60 구매 후14, 선택 전투 포함110에서 구매 후50을 검증했다. 레벨업 3지선다는 없다.

## MCP 승인 진단

이전 거부 도구는 `mcp__godot_ai__session_manage`, `mcp__godot_ai__editor_state`, `mcp__godot_ai__scene_manage`이고 원문은 `MCP tool call requires approval, but approval policy is never`였다. 현재 동일 등록 도구의 상태·열린 씬 조회는 모두 성공했다. 프로젝트 identity와 파일 씬 없음도 확인했다.

유효 정책 never는 실행환경에서 전달됐다. 사용자·프로젝트 config에는 approval_policy나 Godot 개별 approval_mode 설정이 없다. 현재는 변경 불필요하다. 필요 시 최상위 `approval_policy = "on-request"`의 정확한 위치, 개별 도구 prompt 예시, 실행 override의 한계는 [승인 설정 진단](Godot%20MCP%20승인%20설정%20진단-2026.10.03.1737.md)에 기록했다. 권한·신뢰·MCP 설정·AGENTS.md를 변경하지 않았다.

## 검증과 수정

`tools/verify-first-journey.py`는 사용자 저장과 분리한 APPDATA/LOCALAPPDATA에서 import와5개 runner를 실행한다. 모든 단계 exit0, stderr 빈값, 오류0, 기대 마커 확인. [manifest](../docs/verification/first-journey/manifest.json)와 stdout/stderr 원본이 증거다.

| 검증 | 실제 결과 | 증거 |
|---|---|---|
| 규칙·그리기·소비·피해 | 47 검사 통과 | logs/gameplay.stdout.txt |
| 경제·중복 지급·거래 | 통과 | logs/economy.stdout.txt |
| 저장·손상·백업·미래 schema·실패 | 통과 | logs/save.stdout.txt |
| 전체 여정·선택 경로·패배·재개·실패 재시도·설정 | failures=0 | logs/journey.stdout.txt |
| 실제 Viewport 입력 경로로 붓 전투 | 공터·정예 처치, HP100, 회수74 | logs/input-combat.stdout.txt |
| 마지막 UI 수정 후 통합 재검사 | failures=0, exit0, stderr 빈값 | logs/journey-final.stdout.txt |
| 실제 창1280×720·UI150% 재검사 | 저장PNG 성공, exit0, stderr 빈값 | logs/visual-final.stdout.txt |

로그 상대경로 기준은 `docs/verification/first-journey/`다. 실제 headed MCP 입력으로 튜토리얼과 방 이동도 확인했다. 전체 경로의 자동 통합 runner는 일부 진행을 fixture로 설정한다. 별도의 input-combat runner는 피해 함수를 직접 호출하지 않고 마우스 입력을 실제 처리 경로에 전달해 전투를 수행한다. 화면 캡처 fixture의 즉시 처치는 시각 상태 준비이며 전투 검증으로 계산하지 않는다.

검토에서 일시정지 UI/Esc, 저장 재시도 후 메뉴 전환, 재시도의 공짜 잉크 충전, 반지름 있는 투사체 충돌, dummy 위치, 메뉴 중 적 진행, 손상 저장 새게임 처리, 설정 저장, 경계 재진입 점 공격을 수정했다. 소수 좌표 저장의 엄격 readback 실패는 full precision 직렬화만으로 해결되지 않았다. 직렬화 결과를 다시 읽은 canonical snapshot을 비교 기준과 확정 상태로 사용하여 실제 전투 중 자동저장까지 통과했다. [BE 검토](첫%2010분%20BE%20구현%20코드%20검토-2026.10.03.1748.md)에 세부 근거를 남겼다.

기존 D3D12/mobile 렌더러의 실제 창 실행에서 Intel Iris Xe 파이프라인 생성 실패(0x8007000e/0x887a0005)가 발생했다. 해당 실행 오류를 해결하기 위해 renderer를 gl_compatibility로 변경했다. 이후 실제 창 반복 실행은 정상 종료했다. 사용자 autoload·Godot AI plugin·Jolt 설정은 유지했다.

## 화면 인수와 남은 관찰

크림 종이·연필선·코발트 수채화 방향을 메뉴부터 HUD·상점·확인창에 적용했다. 텍스트는 실제 Control이며 설정100/125/150%를 제공한다. 실제 창1280×720,1920×1080,1024×768을 실행했다. 캡처는 viewport 내용이며 OS의 여백까지 찍은 전체 창 사진은 아니다. DPI에 따라 texture 픽셀 수가 창 크기와 다르다. 여백 시작 공격은 별도 입력 검사로 차단을 확인했다.

최종 화면: [메뉴](../docs/verification/first-journey/captures/menu-1280x720.png), [정예 예고](../docs/verification/first-journey/captures/elite-1280x720.png), [복원 전](../docs/verification/first-journey/captures/flower-before-1280x720.png), [복원 후](../docs/verification/first-journey/captures/flower-after-1280x720.png), [상점](../docs/verification/first-journey/captures/shop-1280x720.png). 시각 fixture 상점은 정예 수입50만 보유한 상태이므로 연필 구매 불가 표시가 정상이다.

기능 프로토타입은 인수한다. 맵 건물·문·일부 효과는 초안 형상, 캐릭터는 정적 원화와 간단한 움직임이다. 최종 애니메이션·상세 맵 원화는 완료라고 하지 않는다. QA I/F/S 항목은 자동 기능 증거를 확보했지만 각 항목에서 요구한 연속 수동 영상까지 전부 확보한 것은 아니다. V 항목도 화면 검사와 자동 논리 검사를 구분한다. 외부5명 중4명의 이해도, 실제 약10분의 소요시간, 전체 여정의 처음 사용자 연속 영상은 **미검증**이며 후속 플레이테스트 대상이다. 자동 검사 통과를 모든 상황에서 오류가 없다는 보장으로 확대하지 않는다.

커밋·푸시·배포는 수행하지 않았다. 저장 검증의 재사용 절차는 프로젝트 전용 self-learning 문서로 기록한다.
