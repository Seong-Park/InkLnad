# Ink Land — 수채화 여우 마법사 RPG 첫 버전 설계

작성일: 2026-10-03. 대상: Godot 4.7.2, GDScript.
상태: 재설계 필요. 사용자의 추가 지시로 원작 맵 구조와 캐릭터 메커니즘의 정확한 재현이 필수다. 아래 단순화된 맵·성장·전투 제안은 승인된 원작 재현 설계가 아니며 구현 기준으로 사용하지 않는다.

## 추가 요구 — 원작 재현 우선

수채화 미술, 모바일 가로 조작, 싱글플레이, 색 복원 세계관은 유지한다.
원작의 버전을 먼저 특정하고 맵 연결·게이트·마을·필드·던전 구조를 자료와 대조한다.
캐릭터 타입·성장 그래프·능력치·일반/TM 레벨·스킬 카드·전직·장비·발굴 규칙을 조사해 명세로 작성한다.
임의의 마을 하나/필드 하나, 단순 레벨·업그레이드, 마법탄·범위기·대시 구성은 원작 규칙 확인 전 확정하지 않는다.
사용자는 양 마법형 메커니즘과 독자적인 여우 외형의 조합을 확정했다. 초기판을 원하며 후기판 규칙을 섞지 않는다.
기준 판본은 사용자 선택에 따라 TM이 통합된 2004년 12월 개편 후 초기판이다. 개편 전 네 타입별 TM은 구현 기준에서 제외한다.
판본별 근거와 미확인 항목은 2026-10-03-trickster-early-evidence.md에 기록한다.
자료가 없는 수치와 판본 차이는 미확인 항목으로 표시하고 정확하다고 주장하지 않는다.
참고 조사 시작점: https://en.wikipedia.org/wiki/Trickster_Online 및 당시 지역 지도·직업 공략. 커뮤니티 자료는 원작 공식 자료/당시 플레이 자료와 교차 확인한다.

## 확정 방향

옛 PC 트릭스터의 탐험·사냥·발굴·성장 경험을 참고한 독자적인 싱글플레이 RPG.
모바일 가로 화면, 왼쪽 가상 조이스틱, 오른쪽 공격·스킬 버튼.
주인공은 지팡이를 사용하는 여우 마법사. 붓은 발굴 도구다.
따뜻한 숲속 마을과 수채화 초원에서 시작하며 빛바랜 세계에 색을 되돌린다.
기존 손가락 선 그리기 전투는 버튼식 마법 전투로 교체한다.

## 구현 방식 비교

1. 기존 프로젝트 안에 새 RPG 흐름을 추가하고 검증 후 메인 씬을 전환한다(추천).
   이동·카메라·저장 절차와 종이 미술 자산을 활용하면서 이전 흐름을 비교할 수 있다.
2. 기존 여섯 구역의 전투와 진행 규칙을 직접 수정한다.
   초기 파일 수는 적지만 선 그리기 튜토리얼·보상·저장 규칙이 강하게 연결되어 회귀 위험이 크다.
3. 별도 Godot 프로젝트로 다시 만든다.
   구조는 자유롭지만 기존 작업과 검증 기반을 다시 연결해야 한다.

첫 번째 방식을 기준으로 아래 범위를 제안한다. 기존 미추적 파일과 수정 내용은 사용자 작업으로 보존한다.

## 첫 플레이 범위

마을 하나, 연결된 초원 하나, 의뢰 NPC 하나, 여우 마법사 하나.
마을에서 복원 의뢰를 받고 초원의 몬스터를 처치하거나 붓으로 안료를 발굴한다.
안료를 모아 초원의 복원 지점에서 사용하면 바랜 풀·꽃·나무에 색이 번진다.
마을로 돌아가 완료 보상을 받고 지팡이를 한 단계 개선한다.
첫 복원을 완료하면 다음 지역이 열릴 예정임을 표시한다. 다음 지역 제작은 후속 범위다.

## 모바일 조작과 전투

1280×720을 기준으로 가로 비율에 대응하고 버튼은 화면 가장자리 안전 영역 안에 배치한다.
왼손 이동과 오른손 공격은 서로 다른 터치 ID로 동시에 처리한다.
공격은 사거리 안의 가장 가까운 살아 있는 적을 자동 겨냥한다. 적이 없으면 마나·재사용 시간을 소비하지 않는다.
기본 마법탄, 대상 주변 범위 마법, 이동 방향 짧은 대시를 제공한다.
스킬은 마나와 재사용 시간으로 제한하고 HUD에 표시한다. 마나는 시간에 따라 회복한다.
PC 검증용 WASD/방향키 이동과 공격·스킬 키를 함께 제공한다.
일시정지·포커스 이탈·손가락 해제 시 입력을 초기화해 이동이나 공격이 고착되지 않게 한다.
첫 적은 가까이 다가오는 잉크 얼룩 몬스터로 시작한다. 사망 시 중복 보상을 막는다.

## 붓 발굴과 세계 복원

발굴 지점 근처에서 상황별 붓 버튼을 표시한다.
버튼을 누르면 짧은 붓질과 물감 번짐으로 보물이 드러난다. 이동·피격으로 취소하면 보상은 지급하지 않는다.
주변 적이 위협하는 동안에는 시작을 막고 이유를 안내한다.
완료된 지점은 고유 ID로 저장하고 한 번만 보상한다.
전투 보상과 발굴 보상으로 복원에 필요한 안료를 얻는다.
복원은 조건 충족 후 상호작용으로 실행하며 안료 소비와 복원 플래그를 한 저장 단위로 처리한다.
복원 전후는 같은 지형 배치를 사용해 색의 변화가 읽히게 한다. 밝은 마을은 안전한 거점으로 유지한다.

## 성장과 실패

첫 버전은 경험치·레벨과 지팡이 한 단계 업그레이드만 제공한다.
안료는 복원 자원, 의뢰 보상 화폐는 장비 개선 자원으로 분리해 진행이 막히지 않게 한다.
쓰러지면 마을에서 회복한다. 완료한 발굴과 복원은 유지한다.
새 퀘스트·인벤토리·상점의 대규모 시스템, 직업 선택, 멀티플레이는 후속 범위다.
수치 밸런스는 리소스로 관리하고 첫 플레이 검증 중 조정한다.

## 기존 코드와 새 구조

현재 Main.tscn은 JourneyController, AreaRuntime, PlayerController, DrawController, JourneyUI를 연결한다.
JourneyRules는 A~F 여섯 구역과 선 그리기 도구·적·진행 조건을 함께 정의한다.
PlayerController는 종이 기사 프레임과 키보드 입력을 사용한다.
JourneyState/SaveStore/EconomyService는 스키마 1과 기존 진행 조건을 검증한다.

새 RPG의 시작 씬과 진행 제어, 여우 플레이어, 모바일 HUD, 마법탄, 발굴 지점, 복원 구역을 구성한다.
전투와 발굴은 각각 결과 이벤트를 보내고 진행 제어가 퀘스트·보상·저장에 반영한다.
카메라와 적 이동은 기존 코드를 검토해 재사용 가능한 부분만 활용한다.
RPG 저장은 별도 경로 user://inkland/fox_rpg/profile.json과 명시적인 스키마를 사용한다.
기존 profile.json을 새 진행으로 해석하거나 덮어쓰지 않는다.
기존 저장의 임시 파일·검증·백업 원리를 재사용하되 구형 진행 필드와 검증기는 그대로 적용하지 않는다.
저장 실패 시 성공 메시지를 표시하지 않고 재시도 UI를 제공한다.

## 미술

크림색 종이, 연두·따뜻한 노랑·연한 청록의 수채화 환경.
여우 귀와 꼬리, 작은 지팡이가 작은 화면에서도 구별되는 실루엣.
바랜 초원은 연필과 옅은 회갈색, 복원 후에는 풀·꽃·나무에 투명한 색 겹침.
세계 좌표 배경과 HUD를 분리하고 이동 방향·타격·피격이 읽히는 캐릭터 애니메이션을 제공한다.
최종 주인공·배경 자산은 생성/선정 후 실제 화면에서 확인한다.

## 검증 및 완료 기준

편집 전 프로젝트 정체성과 모든 열린 씬을 확인한다. 열린 씬은 명시적 경로로 편집·저장하고 스크립트 버퍼를 저장한다.
Godot --headless --path godot --import의 stdout·stderr·종료 코드를 확인한다.
게임 규칙 테스트: 적 없는 공격, 중복 처치 보상, 발굴 취소/중복 발굴, 복원 자원 부족, 저장 재시작, 저장 실패.
입력 통합 테스트: 이동과 공격 동시 터치, 터치 해제, 일시정지 복귀, 가장자리 버튼과 발굴 상호작용.
실제 실행 화면에서 여우 표현·가로 HUD·수채화 복원 전후를 캡처해 확인한다.
새 게임 → 의뢰 → 사냥/발굴 → 복원 → 의뢰 완료 → 장비 개선 → 재시작 후 진행 유지가 첫 버전의 완료 기준이다.
검증된 새 시작 씬으로 메인 씬을 전환한다. 타임아웃과 이미지 확인만으로 실행 성공을 판정하지 않는다.
현재 문서는 설계이며 게임 기능의 구현·실행·모바일 기기 검증은 아직 수행하지 않았다.
