## 방향·이동·사용 애니메이션과 시각 상태

시각 루트 Node2D 아래 Body/Scarf/Hand/Tool/FootAnchor/GripAnchor를 합성하는 후보다. BE 런타임이 이 PackedScene을 부착하며 부모 몸체·충돌·카메라를 캐릭터 역할이 수정하지 않는다. 초기에는 AnimationPlayer 하나로 프레임/손 자세를 구동한다. 상태가 복잡해져 AnimationTree를 채택하면 동일 트랙 재생 주체를 하나로 통일한다. 루트 이동·히트박스 생성·피해·잉크 차감·보상용 method track은 넣지 않는다.

| 대상 | 클립 후보 | 표현 및 종료 기준 |
|---|---|---|
| 기사 | idle 2프레임/2초, walk 6프레임/0.6초(4방향) | 접점 고정, 목도리/몸만 작은 흔들림. BE 실제 속도로 walk 재생률을 조절; 정지 시 BE facing 유지 |

기사 방향은 BE facing/이동 상태를 소비하며 커서 방향으로 자동 회전시키지 않는 후보다. 화면 직접 그리기는 기사 반경 안의 임의 선분이며 화구 끝이 선의 출발점·판정점이 아니다. `use_loop`의 손동작은 승인된 그리기 사용 상태만 알린다. 포인터까지 화구를 길게 늘리거나 기사에서 커서로 공격선을 연결하지 않는다. 직접 그린 월드 선·번짐·공격/피격 입자·유효 잔흔은 effect 소유이며 기사 이동으로 기존 잔흔을 끌고 가지 않는다.

상태 우선순위 후보: BE down/귀환 비활성 > hurt 강조 > 손/상체의 BE 사용/고갈/충전 자세. 발 이동 레이어는 별도로 BE actual_velocity/locomotion_state를 따른다. 충전·고갈 중에도 이동 입력은 계속 유효하며 발 walk와 재생률을 유지한다. exhausted는 화구 내림·상체 자세만 덧씌우고, recharge_idle 전체 쉬는 자세는 실제 정지 때만 사용한다. 이동 중 충전은 발 walk에 손/상체의 쉬는 자세만 덧씌워 발 트랙을 덮지 않는다. 시각 우선순위가 이동·공격을 금지하거나 속도를 바꾸지 않으며 down/귀환 시 이동 가능 여부도 BE가 결정한다. 피격 강조가 사용 표시를 덮더라도 BE 공격 상태는 변경하지 않는다. 무적은 BE flag로 윤곽 패턴을 사용하고 반복 섬광은 감소 옵션을 소비한다. 전투 잉크 상태만 화구 자세에 반영하며 회수 잉크·지갑은 HUD에 맡긴다. NPC 복원 전후의 자세는 경제/저장 승인 상태를 소비하고 연출 종료로 영구 상태를 쓰지 않는다.

## 미래 자산과 BE 인계

| 예상 경로(미생성) | 형식·크기 후보 / 기준점 | 소비 주체 |
|---|---|---|
| `godot/assets/characters/{id}/{clip}_{direction}.png` | 투명 RGBA PNG, 위 셀 규격의 가로 스트립(예: 기사 walk 768×128), 모든 프레임 고정 발 접점 | 캐릭터 시각 씬 |
| `godot/assets/characters/tools/{tool_id}.png` | 투명 RGBA64×128, 위 그립/끝 좌표, 상태별 대체 원화는 동일 규격 | 캐릭터 시각 씬; FE 매니저는 원화를 소비해 HUD 아이콘 제작 |
| `godot/scenes/characters/visuals/{id}_visual.tscn` | 시각 전용 PackedScene, Body/Hand/Tool·앵커·위 클립 | BE 기사/적/NPC 런타임 |
| `godot/resources/characters/visuals/{id}_visual.tres` | 시각 Resource, 픽셀 크기 없음; ID·텍스처·클립·발/손 앵커 | 캐릭터 시각 씬/BE 참조 |
| `godot/scripts/characters/visuals/character_visual.gd` | 미래 GDScript 시각 어댑터, 픽셀 크기 없음 | BE 상태를 시각에 적용, 게임 상태 변경 없음 |

BE→시각 제안: entity_instance_id(동종 인스턴스 구분), character_id 또는 enemy_id, tool_id, world_position(발 접점의 참조/검증 값), facing, actual_velocity, locomotion_state, use_state(시작/사용/종료/고갈/충전), hurt/invulnerable/defeated flags, action_phase/progress, reduced_motion. BE 부모 런타임이 월드 위치와 루트 변환을 단독 적용하고 시각 자식은 local 발 접점(0,0)을 유지한다. 위 시각 어댑터의 상태 적용은 클립·방향 원화·손/상체 자세·표시 상태에 한정하며 world_position을 자식 position/global_position에 중복 적용하지 않는다. 이벤트에는 entity_instance_id·event_id를 두어 반복 피격/복원 반응 중복을 막는 후보다. BE가 이동·AI·공격 시작·충돌·선판정과 시간의 진실을 소유한다. 누락 ID는 중립 실루엣+진단으로 인계하며 다른 도구/적 규칙으로 대체하지 않는다. 시각 완료 통지는 장식 종료에만 사용한다.

공용 ID/필드 스키마는 매니저→master 승인 요청, BE 부모 씬 인스턴스화·상태 제공은 gameplay 요청, NPC 복원/구매 결과는 경제 담당 요청, 발/가림 정렬은 map 요청, 선·예고·입자와 윤곽 대비는 effect 협의, HUD 아이콘/감소 옵션은 FE 매니저 요청이다. 앞으로 래스터 제작 시 imagegen 스킬/도구를 적용하되 이번 자산 생성은 하지 않는다.

## 첫 10분 적용·검증·승인

map 흐름 후보에 맞춰 0–1:30 공방 artisan 안내와 기사 walk/use/고갈 자세 → 1:30–2:30 연결 길 이동하며 그리기 → 2:30–4:30 공터 ink_drop 윤곽/피격/처치 → 4:30–5:30 갈림길 도구 교체 → 5:30–7:30 ink_clot_elite 예고·붓/연필 구분 → 7:30–8:30 꽃집 gardener 복원 반응 → 8:30–10 귀환/구매 artisan 반응을 적용한다. 시간·두 도구 지급·정예/NPC 종류는 후보이며 구매로 복원 진행이 막히지 않는 기획을 유지한다.

미래 구현 승인 후 bridge 프로젝트/열린 씬/스크립트 버퍼 확인→라이브 저장·동기화→headless import→변경 시각 씬/통합 테스트 실행→stdout·stderr·명시 종료코드·기대 마커 기록. timeout을 통과로 보지 않는다. (1) 모든 방향/클립의 발 위치·그립·좌우 도구·가림 캡처, (2) 정지/이동 중 멀리 떨어진 유효 선을 그려도 기사에서 선이 시작하지 않음, (3) UI 시작 입력·반경 이탈/재진입·고갈/충전·취소·도구 교체 중 BE 상태와 use 표시 일치, (4) 피격/무적/패배 동시 상태·구역 전환·삭제 뒤 늦은 이벤트 처리, (5) 잔흔 위 다수 적/작은 화면/색 약화·감소 모션에서 윤곽/예고/발 식별, (6) NPC 복원 실패/이미완료/재진입/재로드에서 승인 상태와 반응 일치 및 중복 보상 없음을 BE/QA/effect/FE와 확인한다. 확인 영상·ID/상태 로그·앵커 캡처가 승인 증거다.

실제 문서 자체검토: 기획 우선순위, 직접 그리기·반경·일시 잔흔·연결 구역·분리 자원, 5색·ID·기준점·자산 명세·소유권·미확정 표기를 대조했다. 출발 Git 상태(project.godot 수정, docs/agents/·docs/design/·godot/addons/godot_ai/ 미추적)를 보존하며 이 역할은 이 파일만 작성했다. 구현/headless 테스트는 수행하지 않았다. self-learning 승격 조건인 검증된 해결 경로·실패 패턴·시도한 막힌 접근이 없어 학습 파일을 만들지 않는다. fe-manager에 계획 accepted/revision-required 검토를 요청하고, master에 시점/플랫폼·원화 규격/방향 수·ID/인계 필드·NPC/정예 후보를 구현 전에 확정 요청한다.
