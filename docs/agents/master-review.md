# master 조직과 계획 검토

상태: 조직과 계획의 부문 인수 완료. 현재 검토는 문서 검토이며 게임 실행 검증이 아니다.

## 사용자 결정

화면에 직접 선 그리기, 기사 주변 제한, 잠시 남는 공격 잔흔, 연결된 작은 전투 구역 탐험, 전투 잉크와 구매 재화 분리를 확정했다. docs/design/game-direction.md v0.2에 기록했다.

## 첫 FE 검토

fe-manager, map-designer, effect-designer, character-designer 역할과 fe-plan을 확인했다. UI 표현과 게임 규칙의 책임 분리는 적절하다. 세 시각 워커에게 실제 래스터 그림 제작 시 imagegen 스킬을 읽도록 요청했다. FE 팔레트도 기존 GDD 기준으로 통일하도록 요청했고 매니저가 두 항목을 반영했다고 보고했다.

## BE 최종 인수

gameplay, economy-save, api-db, qa 계획과 be/review-log.md를 읽었다. 전투와 경제·저장은 매니저 피드백 한 차례 후 accepted, API와 QA는 수정 없이 accepted다. runtime 시각 ID와 재개 가능한 논리 보상 ID의 구분을 두 담당이 같은 의미로 수정했고 경제 상태·원정 상태의 저장 인계도 대조했다. 카메라와 테스트 파일 소유권 충돌은 해소되었다. API와 DB는 현재 미도입이며 로컬 플레이 완결에 필요한 역할과 미래 도입 조건을 명시했다. QA는 첫 10분의 정상·패배·조기 귀환·저장 실패와 재시작 흐름을 포함한 Q01–Q14 계획을 제출했다.

## 총괄 피드백

직접 그리기와 기사 주변 제한이 이동의 의미로 연결되고, 임시 잔흔과 충전이 적을 유도하는 전투로 이어지는 계획이다. 맵은 전투 중앙을 낮은 대비로 비우고 시각 담당은 승인된 형상만 표현한다. 원정의 회수 재화가 귀환 구매로 연결되고 영구 복원은 구매 때문에 막히지 않는 후보로 분리됐다. 모든 부문은 최신 사용자 결정을 기존 GDD보다 우선하며 아직 정하지 않은 수치·정책은 제안으로 표시한다. 이를 조직과 계획의 인수 범위에서 승인한다. 실제 조작감, 손맛, 가격·원정 길이와 저장 실행은 아직 검증되지 않았다.

## 역할과 보고 순환 결과

master와 매니저 두 명, 워커 역할 일곱 개의 지시 파일을 구성했다. FE 워커는 세 개의 독립 에이전트로 생성되었고 BE 워커 역할은 도구 한도로 완료 슬롯을 재사용했다. 역할·런타임 ID는 runtime-roles.json, 배정·제출·피드백·수정·승인 근거는 두 부문 review-log.md에서 확인할 수 있다. 캐릭터, 전투, 경제·저장의 실제 수정 순환을 기록했다. 참조 파일과 쓰기 범위는 역할 파일마다 지정했다.

## FE 최종 인수

맵, 효과, 캐릭터의 실제 계획 파일과 fe/review-log.md를 읽었다. 모두 매니저 검토 accepted다. 캐릭터는 월드 변환 중복과 충전·고갈 중 걷기 모션 덮어쓰기 모호성을 수정한 뒤 재검토를 받았다. 부모 게임 몸체가 월드 위치를 소유하고 시각 자식은 로컬 발 접점을 유지한다는 최종 인계는 적절하다. 영구 환경 복원과 일시 공격 잔흔의 표현을 구분하고 피해 및 자원 상태를 BE에서 읽는 방향도 전체 기획에 부합한다. 수치, 자산 규격, ID와 카메라 정책은 후보로 남긴 상태에서 계획을 인수한다.

## BE 초안 수정 요청

gameplay-programmer.md에 카메라 구현을 FE 소유로 적은 문장이 FE 계획과 충돌한다. 카메라 런타임과 Camera2D, 화면에서 월드로의 좌표 변환은 gameplay-programmer 단일 소유로 통일한다. map은 정책과 경계 및 구도 후보를 제공하고 FE 매니저는 가독성과 입력 안정성을 검토한다. QA의 gameplay 테스트 경로와 기능 워커의 단위 테스트도 겹치지 않도록 단위 테스트와 통합 테스트의 소유 경계를 명시한다. BE의 필독에 FE 부문 계획과 제출된 시각 워커 계획을 추가한다. BE 슬롯 인계 때 수정 요청을 전달한다.

## 실행 한도와 재배정

FE의 맵·효과·캐릭터는 각자 새 에이전트로 생성되었다. BE 매니저와 master가 새 BE 워커를 spawn하려 했지만 agent thread limit으로 거절되었다. list_agents에서 root와 BE 매니저 외에 완료된 FE 워커 둘이 남아 전체 4개 슬롯을 차지한 것을 확인했다. 현재 도구에는 close_agent가 없다. 그래서 완료된 effect 슬롯을 gameplay 역할로, character 슬롯을 economy-save 역할로 재배정하도록 승인했다. BE 매니저가 두 followup_task 전달 성공을 보고했다. 다음 역할도 이전 과업 종료 후 해당 슬롯을 재사용한다. 논리 보고와 리뷰는 BE 매니저가 맡으며 기존 FE 문서는 변경하지 않는다. 이 재배정은 새 독립 스레드 생성 성공이 아니다. 조건, 실패한 신규 생성, 재배정 경로를 workflow.md에도 기록했다.

## 구현 전 남은 기획

그리기 반경의 수치, 경계 진입과 이탈 처리, 길이와 유지 시간에 따른 잉크 소비, 고갈 이후 입력 유지 동작, 첫 구현 플랫폼, 카메라 이동 중 그리기 피드백, 첫 10분의 최종 흐름을 정해야 한다. 이 항목들은 조직과 계획 구성에는 지장이 없지만 워커가 승인된 구현값으로 취급해서는 안 된다.

## 문서 검증 결과

2026년 10월 3일 tmp/verify-agent-docs.py를 실행해 역할 10개와 문서 26개의 존재, UTF-8 표시, 조직 인덱스 링크와 실제 필독 경로, 역할 등록 JSON의 연결을 확인했다. 오류 0개, 종료 코드 0이었다. 기존 godot/project.godot의 SHA256은 조직 구성 전과 같았다. 이는 문서와 기존 프로젝트 보존 검증이며 Godot 게임 실행 테스트는 아니다. 사용자 AGENTS.md와 MCP 설정 및 설치 스킬은 수정하지 않았다.

## 후속 기획 기록 v0.3

사용자는 범위 안의 한 지점에 누르고 있어도 물감을 계속 쌓아 공격하고 잉크를 소비하는 방식을 선택했다. 이어 공격 중지 후 약 0.5초 지연 뒤 충전을 시작하는 초기안을 채택했다. game-direction v0.3과 공동 계약에 기록했다. 이전 워커 계획은 당시 기획 기준의 인수 기록이며 최신 규칙과 충돌하는 동일 점 유지·잔흔 정책은 구현 배정 전에 매니저가 갱신한다.

## 후속 기획 기록 v0.4

사용자가 고갈 규칙을 채택했다. 새 공격은 즉시 종료, 기존 잔흔은 남은 수명 유지, 기사 이동은 유지한다. 입력을 유지한 채 자동 충전·재공격하지 않으며 손을 뗀 시점부터 약 0.5초 뒤 충전하고 다시 눌러 공격한다. 기획 기준과 공동 계약에 반영했다. 다음 항목은 도구별 잉크 소비, 충전 속도와 공격 가능한 최소 잉크다.

## 조직 변경: 기획 전담 분리

2026년 10월 3일 사용자 요청으로 /root/planning_agent를 실제 생성했다. planning-agent는 웹 자료 조사·사례 분석·기획 작성과 승인된 기준 반영을 맡는다. master는 기획 작성 업무를 제거하고 전체 흐름 검토·피드백·승인과 부문 인계를 맡는다. 새 역할 필독·산출물·권한과 reports/ 보고 규칙을 planning-agent.md에 기록하고 README/workflow/game-direction/runtime-roles에 반영했다. 최초 자료 조사 보고서를 배정했으며 제출·검토 결과는 후속 기록한다.
