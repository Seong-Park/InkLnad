# 부문 간 공동 계약 v0.1

소유자: master. 현재는 설계 계약 초안이며 구현 API가 아니다. 매니저는 변경을 제안할 수 있다.

## 첫 10분 승인 기준과 과거 초안의 관계

2026년 10월 3일 master가 reports/첫 10분 플레이 상세 기획-2026.10.03.1611.md 수정본을 첫10분 프로토타입의 설계 기준으로 accepted했다. reports/첫 10분 플레이 구현 계획-2026.10.03.1615.md가 다음 실행의 파일·함수 인계 기준이다. 아래 과거 계약 후보와 충돌하면 해당 상세기획과 계획을 적용한다. PC 자유2D필드, 로컬 단일 상태 스냅샷, profile_id+spawn_id+최초처치 보상키, 정예완료 플래그로 무료복원, no-respawn·무손실패배를 첫 범위에서 사용한다. 분산 revision/일반 이벤트버스/원격 API는 요구하지 않는다. 복잡한 과거 후보를 자동 구현하지 않는다. 최종 제품 플랫폼과 확장 난이도는 이 승인에 포함되지 않는다.

## 직접 그리기 입력

UI 계층은 포인터 ID, 화면 위치, pressed/moved/released, UI에 소비된 입력 여부를 게임 입력 계층에 전달한다. 게임 규칙 계층은 화면 위치를 월드 위치로 변환하고 기사 중심 유효 반경 안의 선분을 산출한다. 포인터가 이동 영역·UI에서 시작하면 공격을 시작하지 않는다. 반경 바깥의 점 사이를 연결해 기사 주변을 가로지르는 선이 생기지 않도록 경계 처리를 명시해야 한다. 좌표 변환과 선 판정은 두 계층에 중복 구현하지 않는다.

## 공격과 시각 효과

논리 공격은 stroke_id, tool_id, 월드 좌표 선분 목록, 실제 굵기, 생성 시각, 유효 수명, 소유자를 가진다. 규칙 계층이 유효 길이, 잉크 비용, 대상별 피해와 중첩을 결정한다. effect-designer는 승인된 공격 데이터로 물감 표현을 만들며 표현상의 번짐이 피해 범위를 늘리지 않는다. 장식 잔흔과 피해가 있는 잔흔을 구분한다.

game-direction v0.4에서는 제자리 누르기도 지속 공격과 잉크 소비를 만든다. 이전 gameplay-plan의 동일 점 유지 시 유지비만 소비하고 유효 수명은 갱신하지 않는 제안은 최신 기획에 맞춰 재검토한다. 공격 중지 후 충전 지연 초기값은 약 0.5초다. 고갈하면 새 공격을 즉시 멈추고 기존 잔흔과 이동은 유지한다. 입력을 유지한 채 충전·자동 재공격하지 않으며 손을 뗀 시점부터 지연 뒤 충전하고 새 press로 재공격한다. BE는 고갈 상태와 입력 해제 여부를 구분해 FE에 전달한다. 실제 유지 피해·수명 갱신·중첩과 최소 공격 가능량은 후속 설계다.

## 구역과 카메라

구역 정의는 area_id, 종류, 경계, 연결 출구, 카메라 모드, 스폰 영역, 안전 지점, 완료 조건, 복원 대상 ID를 포함한다. map-designer는 지형 및 구역 표현을 맡고 gameplay-programmer가 이동·적 생성·출구 상태를 맡는다. Camera2D와 카메라 런타임, 화면에서 월드로의 좌표 변환은 gameplay-programmer가 단독 소유한다. map은 프레이밍과 모드 및 경계 후보를 제공하고 FE 매니저는 입력 안정성과 가독성을 검토한다. 카메라 및 전환 정책은 FE와 BE 매니저의 합의 후 master가 확정한다. effect와 캐릭터는 월드 좌표를 사용한다.

## 경제와 저장

전투 잉크, 원정 중 회수 잉크, 마을 지갑, 영구 복원 상태는 별개의 상태다. 구매·복원·보상은 UI가 직접 숫자를 수정하지 않고 게임 규칙 계층에 요청한다. 경제 담당은 가능 여부를 검사하고 결과와 사유를 전달한다. 저장은 버전과 안정적인 ID를 사용한다. 현재 기준은 로컬 단일 플레이이며 원격 API/DB는 별도 요구와 승인 전까지 문서상의 경계만 유지한다.

## 시각 및 데이터 자산

도구·캐릭터·적·구역·복원 대상은 공통 ID로 참조한다. 역할별 계획은 예상 파일 경로, 형식, 크기, 기준점, 애니메이션 목록과 소비 주체를 정의한다. 계획 단계의 경로는 파일이 이미 존재한다는 의미가 아니다. 메인 메뉴 PNG는 참고 자료이고 버튼·텍스트는 실제 Control 노드로 분리한다.

## 검증

논리 검증은 입력, 선분 경계, 자원 비용, 피해 중첩, 보상 중복 방지, 저장 복구를 확인한다. 시각 검증은 피해 범위의 일치, 입력 영역, 잔흔 가독성, 카메라 움직임과 복원 변화를 확인한다. 각 매니저가 부문 검증을 검토하고 master가 첫 10분 플레이 흐름을 검토한다.

## 부문 검토 후 인계 기준

두 매니저의 계획을 대조해 책임 경계를 정리했다. 구현 수치와 데이터 구조의 최종 확정은 후속 설계에서 진행한다.

- 기사 주변 제한은 중심선뿐 아니라 실제 선의 굵기와 끝부분까지 고려한다. 유효 범위의 판정 결과는 gameplay가 effect에 제공한다. 이미 생성한 잔흔의 이동 후 유지 여부는 기획 확정이 필요하다.
- 입력 시 화면 변환과 기사 중심이 같은 표시 시점을 참조해야 한다. 카메라 변화로 입력 점을 다른 좌표로 재해석하지 않도록 gameplay가 한 곳에서 처리한다.
- 긴 드래그에서 먼저 그린 부분과 나중에 그린 부분의 수명, 구역 전환 및 늦은 시각 구독자의 현재 상태를 구별할 수 있어야 한다. 선분별 시간과 snapshot/revision 필드는 구체화할 후보이며 현재 구현 API는 아니다.
- 시각 인스턴스 ID, 재개 후 유지되는 논리 스폰 ID, 전달 이벤트 ID와 보상 중복 방지 키의 의미를 구별한다. gameplay와 economy의 계획은 동일한 논리 ID를 인계하도록 수정했다.
- 재화와 복원 상태는 저장 결과와 함께 다룬다. 임시 상태와 완료 상태를 UI가 구별하고 저장 실패를 성공 연출로 표시하지 않는다. 같은 저장 세대의 원정 상태와 경제 상태를 복구하는 구체적 정책은 economy 계획 후보를 기준으로 검토한다.
- 캐릭터의 월드 변환은 gameplay 부모가 적용한다. 시각 자식의 발 접점은 로컬 기준을 유지한다. 이동 모션과 도구 사용·고갈·충전의 표현을 구분하여 충전 중 이동을 멈춘 것처럼 보이지 않게 한다.
- 기능 워커는 tests/unit/ 아래 자신의 기능 테스트를, QA는 tests/integration/ 통합 검증을 소유하는 경로 후보로 통일했다.
