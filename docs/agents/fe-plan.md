# FE 계획 v0.1

2026-10-03. 기준: game-direction v0.2, contracts v0.1. 현재 계획 단계이며 모든 미래 경로는 예약 제안이다. 최신 직접 그리기가 GDD v0.1의 방향 조준·공격 스틱을 대체한다.

## FE 매니저가 직접 맡는 UI 통합

수채화 책의 크림 종이와 연필 윤곽, 코발트 선택 붓질을 유지한다. 메뉴 PNG는 배경 방향 참고이며 글자와 버튼은 Control로 분리한다. GDD 기본 팔레트로 통일한다: 종이 #F3E5C9, 선화 #3B3430, 코발트 #1749C6, 따뜻한 빛 #D99835, 위험 #8D3154. 비활성은 기본 선화의 명도/패턴 변형을 후보로 검토한다. 제목은 한글 지원 명조 계열 후보, HUD는 한글 지원 고딕 후보를 사용하고 폰트 라이선스/최종 크기는 구현 전 확인한다. 수치·상태는 색 외에 이름/아이콘/윤곽으로 구분한다.

화면 흐름: 메인 메뉴(저장 없음: 새로운 여정에 초기 포커스/이어하기 비활성; 저장 있음: 이어하기에 초기 포커스/현재 지역·복원 표시)→공방 안내→연결 길→공터→갈림길→정예→꽃집 복원→귀환 요약→마을 상점→다음 탐험. 새 여정의 저장 덮어쓰기에는 결과를 명시하는 확인을 둔다. 일시정지/설정/크레딧/종료와 상점·복원 실패 사유도 Control로 통합한다. 저장 손상 때 이어하기를 임의 시작으로 대체하지 않고 경제/저장 담당 결과와 복구 선택을 표시한다.

HUD는 CanvasLayer/Control 아래 앵커와 Margin/BoxContainer를 사용한다. 좌상단 체력과 '전투 잉크' 병/게이지/고갈·충전 표시, 상단 다른 위치에 '이번 원정 회수 잉크' 숫자/주머니, 마을에서는 '마을 지갑' 이름을 표시한다. 우상단 목표·일시정지, 하단 도구 선택, 상점에는 가격·보유 지갑·구매 결과를 표시한다. 구매/복원 요청은 규칙 계층으로 보내고 응답 후 표시한다. UI가 재화/복원 상태를 직접 수정하지 않는다. 두 도구 장착 등 미확정 기능은 후보로만 둔다.

## 터치/마우스 직접 그리기 표현

PC 후보: 이동 키와 마우스 드래그 독립. 터치 후보: 왼쪽 이동 영역과 나머지 월드 그리기 영역 독립. 공격 스틱을 넣지 않는다. 포인터 ID마다 시작 시 UI/이동/그리기 소유를 고정하고 UI에서 시작한 드래그가 월드로 넘어와도 공격을 시작하지 않는다. 이동 손가락과 별개인 한 공격 포인터를 후보로 제안하며 추가 포인터는 공격을 만들지 않는다. 메뉴 진입, 포커스 상실, 포인터 취소에서 release/cancel 의도를 전달한다. 재개 후 새 press를 요구하는 방안은 master 확정 요청이다.

UI→게임 입력: pointer_id, screen_position, pressed/moved/released, consumed_by_ui. BE가 이동 중 카메라를 포함한 좌표 변환과 반경 경계 절단/재진입 처리를 단독 수행한다. FE는 BE 승인 선분·반경·허용/거절 사유를 읽어 범위 링과 커서, 효과를 표현한다. 로컬 미리보기는 장식으로 명확히 구분하고 피해 확정처럼 보이지 않게 한다. 바깥 두 점 사이를 잇는 유령 선과 잉크 부족 구간은 FE가 보간하지 않는다.

## 소유권 및 인계

| 소유자 | 미래 독점 쓰기 범위 | 인계 책임 |
|---|---|---|
| fe-manager | godot/scenes/ui/, scripts/ui/, assets/ui/, resources/ui/ | HUD·메뉴·테마·터치/마우스 표시, 원시 포인터 전달 |
| map-designer | godot/scenes/world/maps_visual/, assets/world/maps/, resources/world/maps_visual/ | 구역 지형/복원 시각, area_id/출구/경계/안전점 제안 |
| effect-designer | godot/scenes/effects/, scripts/effects/, assets/effects/, resources/effects/ | 승인 stroke_id/tool_id/월드 선분/굵기/수명 소비, 장식·유효 잔흔 구분 |
| character-designer | godot/scenes/characters/visuals/, scripts/characters/visuals/, assets/characters/, resources/characters/visuals/ | 시각만, character_id/enemy_id/tool_id·발 기준점·애니메이션 소비 |
| gameplay-programmer(BE) | BE 계획에서 확정할 게임 규칙/런타임 범위 | 카메라 런타임, 좌표 변환, 선 판정, 이동/충돌, AI·스폰·출구, 공격 규칙 |
| economy-save-programmer(BE) | BE 계획에서 확정할 경제/저장 범위 | 재화·구매·보상·복원 상태·저장 응답 |

카메라 정책은 map 제안→FE 시각/입력 안정성 검토→BE 구현 가능성 검토→master 확정. 카메라 코드와 Camera2D 노드는 BE 소유로 제안한다. map은 카메라 모드와 경계 데이터만 제공한다. 런타임 씬은 BE가 FE 시각 씬을 인스턴스화하고 FE는 BE 부모 씬을 수정하지 않는다. 공용 ID/데이터 스키마와 게임 통합 씬은 master에게 변경 요청한다.

## 배정·검토·향후 검증

UI 자산 인계 제안: godot/assets/ui/menu_background.png는 글자 없는 1920×1080 RGBA 배경, 선택 붓질은 512×128 RGBA 9-patch 후보, 도구/병/주머니 아이콘은 128×128 RGBA와 중심 기준점, godot/resources/ui/inkland_theme.tres는 공용 Theme 후보다. 아직 파일은 만들지 않는다. 버튼 텍스트는 이미지에 굽지 않는다. 메뉴 전환/선택/저장 표시의 UI 애니메이션은 fe-manager가 소유하고 effect 역할과 중복하지 않는다.

접근성 제안: 기본 가로 화면과 안전 영역을 먼저 검토하고 터치 목표 48dp 상당, 1080p 기준 메뉴 본문 28px 후보를 실제 기기에서 확인한다. 한글 텍스트 확대 시 컨테이너가 줄바꿈/스크롤을 허용한다. 포커스는 윤곽과 붓질로 함께 표시하며 메뉴에서 뒤로 돌아오면 원래 항목을 복원한다. 설정은 글자 크기·흔들림/깜박임/페이지 전환 감소·피해 숫자·개별 음량·키 안내를 제공하는 후보이며 입력 재지정은 BE의 입력 매핑 변경 요청으로 인계한다. 게임패드의 화면 직접 그리기 방법은 미확정으로 master에게 요청하고 조준 스틱을 확정하지 않는다.

map→effect→character 배정 순서, 기본 한 워커 완료 및 리뷰 후 다음 생성. master가 명시적으로 슬롯을 허용하면 독립 과업 두 명을 실행할 수 있으며 전체 한도는 4명이다. 각 워커는 fe/ 아래 자신의 plan 파일 하나만 쓴다. 문서 리뷰는 직접 그리기/기사 반경/일시 잔흔/연결 구역/분리 자원, 소유권·참조·ID·자산 명세를 비교한다. 실행하지 않은 수치와 정책은 제안으로 표시한다.

미래 구현 승인 이후: 에디터 프로젝트/열린 씬과 스크립트 버퍼 확인→라이브 저장→headless import→변경 씬/테스트 실행→stdout/stderr/종료 코드/기대 마커 확인. 시각 수동 확인은 저장 없는/있는 메뉴, 작은 가로 화면과 넓은 창, UI 시작 드래그·멀티터치·카메라 이동 중 선·반경 이탈 재진입·고갈·충전·잔흔 종료·꽃집 복원 전후·귀환 지갑·구매 거절을 포함한다. 읽기 어려우면 배경/장식을 줄이고 실제 판정 경계와 적 예고를 우선한다. 현재는 이 검증을 실행하지 않는다.
